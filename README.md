# 喵绘 · MIAO STUDIO

像素手账式的中文生图台。左边是大图，右边是黄纸条和画面设定。示例图片会标明「示例」，不会被写成生成历史。

没有配置渠道时，管理员会在创作台右侧看到 **配置渠道**。填接口地址、密钥和模型后保存。密钥写进这台服务器的 `.data/provider.json`，页面不再显示它，也不会进仓库。创作者和查看者看不到这张表，也不能改。按「开始生成」在保存之前会失败，不会假装出了一张图。

## 本地运行

```bash
npm install
npm run dev
```

开发服务器监听 [http://127.0.0.1:43123](http://127.0.0.1:43123)，用局域网地址打开也可以，例如 `http://192.168.2.18:43123`。生图服务如果跑在同一台电脑上，渠道请写 `http://127.0.0.1:端口/v1`，不要写创作台自己的 `43123`。页面用局域网 IP 打开时，程序也会把指向本机的渠道地址改走 `127.0.0.1`。改过 `next.config.ts` 后要重启 `npm run dev`。

```bash
npm test
npm run typecheck
npm run lint
npm run build
```

## 页面

- `/` 创作台：提示、参考图、模型 / 画幅 / 数量 / 风格、高级设置、生成、取消、大图、下载、复用参数
- `/gallery` 作品集：只收真正生成、并按账号存在服务器上的图
- `/prompts` 提示词：这个账号在服务器上的句子
- `/login` 登录。第一次打开先创建管理员
- `/members` 成员，只有管理员能进
- `/account` 改自己的显示名和密码

作品、提示词和示例收藏写在服务器的 `.data/library/`，按账号分开。没提交的草稿仍在这台浏览器里。作品最多 40 条，提示词最多 100 条，单张图不超过 8MB。示例收藏会一直带着「示例」标记。

## 配置生图服务

在创作台右侧填写这三项并保存即可。只在本机打开页面时能保存（`localhost`、`127.0.0.1` 或局域网地址）。

也可以复制 `.env.example` 为 `.env.local`，在服务器上填写。环境变量三项都在时，以环境变量为准，页面不能覆盖：

```bash
IMAGE_API_BASE_URL=https://api.openai.com/v1
IMAGE_API_KEY=
IMAGE_API_MODEL=gpt-image-1
```

不要加 `NEXT_PUBLIC_`。密钥只在 Route Handler 里读取。状态接口 `/api/provider` 和生成接口 `/api/generate` 都不会把它返回给浏览器。

适配器按 OpenAI 兼容的 Images API 转发：

- 文生图：`POST {BASE}/images/generations`
- 带参考图：`POST {BASE}/images/edits`

风格会写进提示词，不是供应商的独立参数。

### 内置模型能力

| 模型 | 画幅 | 数量 | 参考图 | 排除内容 / 种子 / 步数 |
| --- | --- | --- | --- | --- |
| `gpt-image-1` | 1:1、5:4、4:5、4:3、3:4、3:2、2:3、16:9、9:16、21:9。官方接口只有三档像素，相近比例会落到同一尺寸 | 1–4 | PNG / JPEG，最多 4 张 | 不支持 |
| `dall-e-3` | 1:1、16:9、9:16 | 1 | 不支持 | 不支持 |
| `dall-e-2` | 1:1 | 1–4 | 仅一张正方形 PNG | 不支持 |
| 其他模型 id | 默认只有 1024 方图 | 1 | 默认不支持 | 默认不支持 |

`dall-e-2` 与 `dall-e-3` 会带 `response_format=b64_json`。`gpt-image-1` 不带这个字段。

如果网关确实接受额外字段，再用环境变量打开，不要提前打开：

```bash
IMAGE_API_CAPABILITIES=negative,seed,steps,reference
IMAGE_API_SIZE_MAP=1:1=1024x1024,4:3=1536x1024,3:4=1024x1536
```

未知字段不会被当成已经生效。模型不支持的选项，服务器直接返回 400，而不是静默丢掉后再报成功。

这次交付没有供应商密钥，也没有对真实接口发过请求。生成功能要等上面的环境变量配好并单独验证之后才算接通。

## 登录和角色

第一次打开会要求创建管理员。之后用账号密码登录。会话是 HttpOnly cookie，大约 14 天。密码用 scrypt 存在 `.data/users.json`，不进仓库。

| 角色 | 能做的事 |
| --- | --- |
| 管理员 | 配置渠道、管理人员、看调用记录、生成。看不到别人的作品图 |
| 创作者 | 生成图片，只看自己的作品。不能改渠道，也不能管成员 |
| 查看者 | 看创作台和自己的收藏。不能生成 |

作品和提示词在服务器上，按账号分开，只能本人读取。管理员在「调用记录」里看到每次生图请求的账号、时间、提示、模型和成败，不包含图片。记录最多留 400 条。模型下拉只影响这一次生成，默认模型要管理员在「配置渠道」里改。

## 安全

- 服务地址不能带账号、查询参数或片段。公网地址必须是 https。本机和局域网地址可以用 http。云元数据地址仍然拒绝。结果图如果是 URL，下载前再查一次，内网结果图不会下载，也不会把 API 密钥带到那个地址。重定向不会被跟随。
- 参考图只接受 PNG、JPEG、WebP，要和文件头一致，单张最多 4MB，最多 4 张。
- 生成、保存生图服务和成员管理都要登录。查看者调生成会得到 403。进程内大约每分钟每 IP 8 次、全局 30 次。这个限制挡不住伪造的 `X-Forwarded-For`，也挡不住多实例。
- 这套登录适合连到这台服务器的几个人共用。还没有按人计费。作品存在服务器磁盘，不在各人的浏览器里。
